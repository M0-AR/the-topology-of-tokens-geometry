The expensive features lost to eight cheap ones.

Leave-one-corpus-out prediction is the hard test: train on five languages, predict the sixth. Where topology helped — and where it did not

Change in MAE when adding topology, by corpus (H1)
Topology improved held-out compression only for Python code (MAE 0.273 → 0.192). It degraded every natural-language corpus. A benefit that appears in one cluster out of six does not survive leave-one-corpus-out.

12 US equities · 10 years of daily bars · LOCO-style transfer

Adding topology moved compression error by −44.28 bytes per token on a 24-row out-of-market test (95% CI [−92.97, −20.37], p = 0.999) — a large degradation. BPB delta was −8.42 (p = 1.0). Within-market, the full model is “less bad” than baseline for compression (R² −0.214 vs −0.332) but the difference is not significant (bootstrap p = 0.277).

07 · How it was done

A protocol frozen before the answer was known.

The confirmatory decision rules, feature sets, and alpha grid were written down before model training. Five execution deviations are documented, none of which changes a decision rule. That is what makes a negative result trustworthy.

STEP 01

Freeze the protocol

Hypotheses, primary targets, feature sets, LOCO design, 2,000 permutations, 2,000 cluster-bootstrap resamples, Holm correction.

STEP 02

Build six corpora

English Wikipedia, Python code, and Chinese, Hungarian, Arabic, and Swahili Wikipedia. Roughly 9.5k train / 1.2k validation / 1.2k test documents per corpus, split by hash.

STEP 03

Train 36 tokenizers

BPE and Unigram at 8,192 / 16,384 / 32,768 vocabulary sizes across six corpora. Byte-reversibility audited: BPE 18/18, Unigram 12/18.

STEP 04

Measure 80 features

Eight cheap statistics plus 72 persistence descriptors from a 256-token embedding cloud and a 256-token co-occurrence graph. Ripser and GUDHI agree on all 24 comparisons.

STEP 05

Train 36 language models

Six-layer decoder, d_model 256, 8 heads, context 1,024, 1,500 steps, two seeds per BPE configuration. 13.4M parameters. 0.695 GPU-hours total.

STEP 06

Predict the held-out language

Leave-one-corpus-out ridge regression with nested alpha selection. Permutation tests and cluster bootstrap. Holm correction across H1–H4.

STEP 07

Stress-test on markets

Twelve US equities over ten years of daily bars. The same feature recipe, transferred out of domain. It did not transfer.

What “leave-one-corpus-out” means

Imagine you have measurements for English, Chinese, Hungarian, Arabic, Swahili, and Python. To test whether a feature generalises, you hide one language entirely, fit the model on the other five, and predict the hidden one. Repeat six times.

This is much harder than random cross-validation, which leaks corpus-specific quirks into both train and test. A feature that only memorises “which corpus am I?” fails LOCO. Topology features failed LOCO.

The eight-feature baseline

These are deliberately boring. That is the point: the comparison asks whether 72 sophisticated descriptors beat the measurements any competent team already has.

Extend it

Six follow-up experiments go beyond the pre-registered null: merge-list truncation, persistent homology on the BPE merge graph, scale-normalized topology, a per-corpus scaling law, a tokenizer health check, and a packaged benchmark. The strongest result is scale planning inside a corpus: merge-graph features lift within-corpus unseen-size R² from 0.575 to 0.934 (Δ +0.359, 95% CI [0.196, 0.705], permutation p = 0.0083). Cross-corpus transfer still fails, and the report keeps that failure visible. Three further invention candidates — persistence-selected merge cores, merge-graph compatibility, and a merge-filtration persistence descriptor — were pre-registered and killed; the negative result is public. Two follow-up tests then checked the diagnosis: C4 continued BPE on target text and passed (6/6 primary comparisons, mean relative gain 123.0%), but it is a replication of published continued-BPE work with a measured English-retention cost; C5 tokenizer-aware data selection was killed (0/6 positive, 6/6 negative). Neither is a novelty claim.

12 · Questions people actually ask

The short answers.

So topology is useless for tokenizers?
Not in general — useless for this prediction problem, under this protocol. Persistent homology is a legitimate tool for shape analysis. Here, 72 topology descriptors failed to improve out-of-corpus prediction of compression or BPB beyond eight cheap statistics, and they degraded it. One exploratory partial association survived correction, but its interval crosses zero. The correct claim is narrow and defensible.
Why is a negative result worth publishing?
Because teams are already spending engineering time on sophisticated tokenizer features without a benchmark. A pre-registered negative result with a frozen protocol, 2,000 permutations, and a public artifact trail prevents repeated dead ends. It also gives reviewers a baseline they can trust: 0.974 R² from eight features is a high bar.
Does a lower BPB always mean lower cost?
No. BPB measures how well a model predicts the next byte; API pricing is per token. The bridge is bytes per token: for the same text, tokens = bytes ÷ bytes-per-token. A tokenizer with better compression can still be more expensive if the provider prices tokens differently, caches aggressively, or uses a different tokenizer than the one you measured. Always map the measurement onto your actual contract.
Why were only BPE tokenizers used for language models?
The confirmatory question targets the tokenizers used by production decoder-only LLMs, which are overwhelmingly BPE. Training 36 additional Unigram language models would have doubled GPU cost without changing the primary hypothesis. Unigram rows still have compression and the full 80-feature set, which is why the explorer can show them — but their BPB field is honestly empty.
What exactly is persistent homology, in one paragraph?
Imagine growing a thin shell around every point in a cloud. At first there are many disconnected blobs. As the shell grows, blobs merge, loops appear, and loops close. Persistent homology records the birth and death of those features across every scale. A long-lived loop is a strong topological signal; a short-lived one is noise. The “persistence” numbers in this repo summarise how much structure survives across scales.
Can I use this with my own corpus?
Yes. Point the config at a text corpus, train tokenizers with the provided CLI, extract features, and run the same analysis. The pipeline is deliberately modular. The smoke profile runs on CPU in minutes with tiny vocabularies; the full profile needs a GPU for the language-model stage. Start with the reproducibility guide.
What is the single most important number?
0.974. That is the leave-one-corpus-out R² of the eight-feature baseline for held-out compression. Any added feature set has to beat it out of corpus. Remember that number and you can evaluate most tokenizer-feature claims in one sentence.
